1. Introduction

BackupPro v3.0 is a comprehensive professional backup suite designed for IT technicians, system administrators, and power users who need reliable data protection. Whether you're backing up a single workstation or managing backups across multiple systems, BackupPro provides the tools you need.

🎯 Key Features at a Glance:

  • Quick User Profile Backup - One-click backup of user data with OneDrive support
  • Folder Synchronization - Mirror folders with optional ZIP compression
  • System Imaging - Full disk backups via Windows Backup (VSS) or DISM
  • WinPE Recovery Media - Build a bootable ISO/USB that bundles BackupPro and your restore scripts for bare-metal recovery
  • App Inventory Migration - Export installed apps (winget) with a one-click reinstall script
  • Environment Variables Backup - Preserve and restore user/system environment settings
  • Browser Data Rescue - Export bookmarks and settings from all major browsers
  • WiFi Password Export - Save all WiFi credentials to a text file
  • Restore Wizard - Easy recovery of backed up data
  • Scheduling - Automate backups via Windows Task Scheduler
  • Multi-Channel Notifications - Email, SMS text, and ntfy push alerts when operations complete

Who Should Use BackupPro?

  • IT Technicians - Quick backups during system migrations and repairs
  • System Administrators - Scheduled backups for workstations and servers
  • Home Users - Simple data protection for important files
  • Managed Service Providers - Deploy and manage backups across client systems

2. System Requirements

Minimum Requirements:

  • Operating System: Windows 10 (64-bit) or Windows 11
  • Memory: 4 GB RAM
  • Disk Space: 50 MB for application
  • Python: Python 3.8 or higher (for running .py version)
  • Dependencies: customtkinter library

Recommended:

  • Operating System: Windows 11 23H2 or later
  • Memory: 8 GB RAM or higher
  • Administrator Rights: Required for disk imaging and system-level operations
  • Network Storage: NAS or network share for remote backups
⚠️ Important: Some features require Administrator privileges. Right-click the application and select "Run as Administrator" for full functionality.

3. Installation

BackupPro can be run either as the pre-compiled backuppro3.exe (simplest, no Python required) or directly from the backuppro3.py source.

Option A: Run the Compiled Executable

  1. Copy backuppro3.exe to a permanent location
  2. Right-click and select "Run as Administrator" (recommended, required for disk imaging and WinPE features)
💡 Note: The exe keeps its own backup_config.json and backup_log.txt in whatever folder it's run from - keep it in a stable location so your settings persist.

Option B: Run from Python Source

  1. Install Python 3.11+ from python.org (check "Add Python to PATH")
  2. Install the one required package:
    pip install customtkinter
  3. Verify installation:
    python -c "import customtkinter"
  4. Right-click backuppro3.py and select "Run as Administrator" (recommended), or open Command Prompt as Admin and run:
    python backuppro3.py
💡 Tip: Create a desktop shortcut with "Run as Administrator" enabled for quick access. Right-click the shortcut → Properties → Advanced → Check "Run as administrator"

First Launch:

On first launch, BackupPro will:

  • Check for Administrator privileges
  • Create configuration files (backup_config.json)
  • Initialize the log file (backup_log.txt)
  • Test NAS connectivity (if configured)

5. Quick User Profile Backup

The Quick User Profile Backup feature automatically detects the current user and backs up all important personal data in one click.

What Gets Backed Up:

  • 🖥️ Desktop (including OneDrive Desktop)
  • 📄 Documents (including OneDrive Documents)
  • 🖼️ Pictures (including OneDrive Pictures)
  • 🎬 Videos
  • ⬇️ Downloads
  • 🎵 Music
  • ⭐ Favorites
  • 🎮 Saved Games

How to Use:

  1. Click the 🏠 Quick Profile Backup button in the header
  2. Review the confirmation dialog showing:
    • Current username
    • Profile location
    • Folders to be backed up
  3. Click Yes to continue
  4. Select destination folder (external drive, network share, etc.)
  5. Review the final confirmation showing source and destination
  6. Click Yes to start the backup
  7. Monitor progress in the Activity Log
  8. When complete, choose to open the backup folder

🔍 OneDrive Detection

BackupPro automatically detects and backs up OneDrive folders! If your Desktop, Documents, or Pictures are redirected to OneDrive (Personal or Business), they will be found and backed up correctly.

The backup will check:

  • Standard Windows locations (C:\Users\Username\Desktop)
  • OneDrive Personal (C:\Users\Username\OneDrive\Desktop)
  • OneDrive Business (C:\Users\Username\OneDrive - Company\Desktop)
  • Windows Registry redirects

If multiple versions exist, both will be backed up with clear labels.

Backup Location:

Backups are stored in timestamped folders:

UserBackup_Username_20260207_143052

Estimated Time:

  • Small profile (<10 GB): 5-15 minutes
  • Medium profile (10-50 GB): 15-45 minutes
  • Large profile (>50 GB): 1+ hours
💡 Best Practice: Run Quick Profile Backup before:
  • Windows updates
  • System migrations
  • Hardware replacements
  • Major software installations
  • Computer repairs

6. Quick Sync

The Quick Sync feature provides flexible folder synchronization with optional compression.

Sync Modes:

1. Mirror Mode (Default)

Creates an exact mirror of the source at the destination. The destination will match the source completely.

⚠️ Warning: Mirror mode will DELETE files in the destination that don't exist in the source!

2. Compression Mode (ZIP Archive)

Creates a compressed ZIP archive of the source folder, saving 50-70% disk space.

  • Creates timestamped ZIP files
  • Automatically excludes cache and junk folders
  • Perfect for archiving projects
  • Displays final archive size

How to Use Quick Sync:

Basic Sync:

  1. Go to the Quick Sync tab
  2. Click 📁 Browse next to "Source Folder"
  3. Select the folder you want to backup
  4. Click 📁 Browse next to "Destination Folder"
  5. Select where to store the backup
  6. Click ▶️ RUN SYNC
  7. Confirm the operation

Compressed Archive:

  1. Follow steps 1-4 above
  2. Check 📦 Create ZIP archive
  3. Click ▶️ RUN SYNC
  4. Archive will be created with timestamp:
    FolderName_20260207_143052.zip

Dry Run (Preview):

  1. Check Dry Run (preview only, no changes)
  2. Click ▶️ RUN SYNC
  3. Review what would be copied without making changes
  4. Uncheck Dry Run and run again to execute

Excluded Folders:

When creating archives, these folders are automatically skipped:

  • node_modules - JavaScript dependencies
  • .git - Git repositories
  • __pycache__ - Python cache
  • Cache and cache - Various cache folders

Saving as Profile:

Save frequently used sync configurations:

  1. Configure your source and destination
  2. Click 💾 Save as Profile
  3. Enter a profile name (e.g., "Weekly Documents Backup")
  4. Access it anytime from the Profiles tab
💡 Use Cases:
  • Mirror Mode: Daily backups, keeping an exact copy
  • Compression Mode: Archiving completed projects, monthly archives
  • Dry Run: Testing new backup configurations

7. Disk Imaging

Create full system drive images using Windows Backup (wbAdmin). Perfect for disaster recovery.

⚠️ Administrator Required: Disk imaging requires BackupPro to be run as Administrator. Right-click and "Run as Administrator" before using this feature.

What is a Disk Image?

A disk image is a complete backup of an entire drive, including:

  • Operating system
  • Installed programs
  • System settings
  • All user data
  • Boot information

How to Create a Disk Image:

  1. Ensure BackupPro is running as Administrator
  2. Go to the Disk Image tab
  3. Select Drive to Image (usually C:)
  4. Click 📁 Browse next to "Backup Destination"
  5. Select destination (must be different drive, network share, or external drive)
  6. Set Keep Last N Backups (default: 5)
  7. Click ▶️ START IMAGING
  8. Confirm the operation
  9. Wait for completion (30+ minutes typical)

Backup Retention:

BackupPro automatically manages disk images based on your retention setting:

  • Keep: 3 - Keeps the 3 most recent backups
  • Keep: 5 - Keeps the 5 most recent backups (default)
  • Older backups are automatically deleted to save space

Naming Convention:

SystemImage_C_20260207_143052

Storage Requirements:

Drive Size Image Size (Approximate) Time Required
250 GB (50% used) ~125 GB 30-45 minutes
500 GB (50% used) ~250 GB 60-90 minutes
1 TB (50% used) ~500 GB 2-3 hours

Restoring from Disk Image:

To restore a system image:

  1. Boot from Windows installation media
  2. Select "Repair your computer"
  3. Choose "System Image Recovery"
  4. Browse to your backup location
  5. Follow the on-screen wizard
⚠️ Important:
  • Cannot backup to the same drive being imaged
  • Network share must be accessible and have sufficient space
  • External drive must be connected before starting
  • Do not disconnect drives during imaging
💡 Best Practice: Create a disk image:
  • After fresh Windows installation and setup
  • Before major updates
  • Monthly for critical systems
  • Before significant system changes

7.1 DISM System Image (Alternative Method)

Below the wbAdmin imaging controls, BackupPro offers a second, file-based imaging method using DISM (Deployment Image Servicing and Management), Microsoft's own OS deployment tool. It captures a folder or drive into a single .wim file.

DISM vs. wbAdmin - Which to Use:

Method Best For Notes
wbAdmin (CREATE SYSTEM IMAGE) Live, running system drive (C:) Uses Volume Shadow Copy (VSS) to snapshot open/locked files - the reliable choice for imaging a drive Windows is actively running from
DISM (Capture Image) Non-system drives, offline partitions, or capturing from WinPE Not VSS-aware - capturing a live C: drive can fail if another process has a file open (see Troubleshooting)
⚠️ Capturing a Live C: Drive with DISM: If you select the system drive as the DISM source, BackupPro warns you and offers to exclude common lock-prone files (pagefile.sys, hiberfil.sys, swapfile.sys, DumpStack.log.tmp, OneDrive's sync-staging folder, etc.). This reduces but doesn't eliminate the risk of failure - for a fully reliable full-OS capture, use wbAdmin instead, or boot into WinPE Recovery Media and capture from there.

How to Capture a DISM Image:

  1. Go to the Disk Image tab and scroll to DISM System Image
  2. Click 📀 Capture Image (DISM)
  3. Select the folder/drive to capture and where to save the .wim file
  4. Enter a name for the image
  5. Confirm and wait for the capture to complete

Restoring a DISM Image:

Click 📝 Generate DISM Restore Script to create a dism_apply.ps1/.bat pair set up to restore the image via dism /Apply-Image plus bcdboot. This is meant to be run from WinPE on the target machine after formatting the destination disk - review and edit the drive-letter placeholders in the script for the target hardware before using it. Bundle the generated folder into your WinPE Recovery Media so it's available at restore time.

7.2 Backing Up to a NAS / Network Share

Both wbAdmin and DISM can target a network destination, but there are two Windows-specific quirks worth knowing about:

Mapped Drive Letters Aren't Supported by wbAdmin:

If you browse to a mapped drive (e.g. V:\Backups), BackupPro automatically detects this and offers to convert it to the real network path (e.g. \\192.168.1.60\Share\Backups) before starting - wbAdmin rejects mapped drive letters outright.

NAS Login Prompt:

Administrator-elevated backups run in a different Windows logon session than your normal desktop, so they can't see your everyday mapped-drive login even if the drive works fine everywhere else. When BackupPro detects a network destination, it shows a 🔐 NAS Login Required dialog asking for the NAS username and password directly. Check Remember in Settings to save them so you're not asked every time - see Settings → NAS Login.

💡 Tip: The login dialog pre-fills the username from your existing mapped-drive connection when it can find one, so you often only need to type the password.

7.3 "Another Backup or Recovery Operation Is In Progress"

If wbAdmin reports this error and you're sure nothing is genuinely running, BackupPro has a one-click fix: click 🔄 Stuck on "another backup is in progress"? Reset Backup Service below the imaging button. This restarts the Windows Block Level Backup Engine service (wbengine), which clears the stuck state. See Troubleshooting for more detail.

8. WinPE Recovery Media

The WinPE Media tab builds a bootable Windows PE recovery ISO or USB drive that bundles your restore scripts - and optionally BackupPro itself - so you can recover a machine even when Windows won't boot at all.

🥾 What You Can Bundle Onto the Media:

  • Your App Inventory export and restore script
  • Your Environment Variables backup and restore script
  • A DISM restore script for applying a captured .wim image
  • The compiled BackupPro.exe itself, so you can run backups/restores directly from the recovery environment

Requirements: The Windows ADK

Building WinPE media requires the Windows Assessment and Deployment Kit (ADK) plus its separate Windows PE add-on - both are free Microsoft downloads, not included with BackupPro. The WinPE Media tab automatically checks for these and shows a clear ✅/❌ status.

If not found, click 🔗 Open Windows ADK Download Page (or the same prompt appears if you try to build without it) to go straight to Microsoft's official download page. Install both the ADK and the WinPE add-on, then reopen the tab.

⚠️ Administrator Required: Building WinPE media requires BackupPro to be running as Administrator.

How to Build Recovery Media:

  1. Go to the WinPE Media tab
  2. Under Restore Content to Include, click ➕ Add Folder to Include for each App Inventory / Environment Backup / DISM Restore folder you want bundled in
  3. Under BackupPro Application, check Include BackupPro on this WinPE media if you want the full app available (it auto-detects a compiled backuppro3.exe next to the script and warns if it looks older than your current source)
  4. Choose the Architecture (amd64 for almost all modern PCs)
  5. Leave Add PowerShell + DISM cmdlets support checked if you plan to run any .ps1 restore scripts from the media
  6. Choose Output: ISO File (burn to disc or use with virtual media) or USB Drive
  7. Click 🥾 BUILD WINPE RECOVERY MEDIA
  8. You'll be asked where to build the temporary workspace (needs a few GB free), then where to save the ISO - or which USB drive to write to
🛑 USB Drive Output Erases the Drive Completely: Building directly to a USB drive formats it entirely. BackupPro requires you to type the drive letter to confirm before proceeding - there is no undo. Back up anything on that USB drive first.

Using the Recovery Media:

Boot the target machine from the ISO/USB (may require changing boot order or using a one-time boot menu, typically F12/F11/Esc/Del depending on the manufacturer). A recovery menu appears offering:

  • Launch BackupPro (if bundled) - run backups/restores directly
  • Open a command prompt in the restore scripts folder - run your generated .ps1/.bat restore scripts
  • Open a plain command prompt - for manual recovery work (diskpart, dism, bcdboot, etc.)
  • Reboot
💡 Best Practice: Build fresh WinPE media whenever you rebuild backuppro3.exe with new features - the media only contains whatever version of the app and scripts existed at build time.

9.3 App Inventory Migration

Exports a list of your installed applications via winget and generates a one-click script to reinstall them all on a clean Windows install - the missing piece for a full new-PC migration.

What Gets Created:

  • apps.json - the winget package list, used to reinstall everything
  • winget_list.txt - a human-readable reference list
  • restore_apps.ps1 / restore_apps.bat - double-click after a clean install to reinstall every app via winget import

How to Use:

  1. Go to the Tools tab
  2. Click 📦 Export App List + Restore Script
  3. Choose a destination folder
  4. Copy the resulting AppInventory_<timestamp> folder to a USB drive, or add it to your WinPE Recovery Media
⚠️ Requires winget: If winget (the "App Installer") isn't installed, BackupPro tells you and skips the JSON export - install App Installer from the Microsoft Store first.

9.4 Environment Variables Backup

Backs up your user (and, if run as Administrator, system) environment variables to .reg files, plus a plain-text snapshot and a restore script.

What Gets Created:

  • HKCU_Environment.reg - your user-level environment variables
  • HKLM_Environment.reg - system-level variables (only if run as Administrator)
  • environment_variables.txt - a readable snapshot for quick reference
  • restore_environment.ps1 / .bat - re-imports both files, automatically detecting whether it's running elevated before attempting the system-level key

How to Use:

  1. Go to the Tools tab
  2. Click 🖥️ Backup Environment Variables
  3. Choose a destination folder
💡 Combine With App Inventory: Together, App Inventory + Environment Backup form a complete migration kit - run both generated scripts after a clean Windows install to get your apps and custom environment settings (PATH entries, custom variables, etc.) back the way you like them.

10. Restore Wizard

The Restore Wizard helps you browse and recover files from your backups with ease.

How to Use the Restore Wizard:

Step 1: Select Backup Location

  1. Go to the Restore tab
  2. Click 📁 Browse next to "Backup Location"
  3. Navigate to where your backups are stored (external drive, network share, etc.)
  4. Select the folder containing your backups

Step 2: Scan for Backups

  1. Click 🔍 Scan for Backups
  2. BackupPro will search for backup folders
  3. All found backups will be listed with:
    • Backup name
    • Date and time
    • Size in MB

Step 3: Browse or Restore

For each backup found, you can:

  • 📂 Open Folder - Browse backup contents in Explorer
  • 🔄 Restore - Copy files to a location of your choice

  1. Click 🔄 Restore on the desired backup
  2. Review backup details in confirmation dialog
  3. Click Yes to continue
  4. Select restore destination folder
  5. Monitor progress in Activity Log
  6. Choose to open restored files when complete

Backup Types Recognized:

  • UserBackup_* - User profile backups
  • BrowserBackup_* - Browser data backups

Selective Restore:

To restore only specific files:

  1. Click 📂 Open Folder on the backup
  2. Browse the backup in Windows Explorer
  3. Copy only the files/folders you need

💡 Best Practice:
  • Test your backup by browsing it before you need to restore
  • Restore to a temporary location first to verify files
  • Don't restore directly over existing files without backup
  • Keep multiple backup generations for safety
⚠️ Note: System images must be restored using Windows Recovery Environment, not the Restore Wizard.

12. Scheduling

Automate your backups using Windows Task Scheduler integration.

How Scheduling Works:

BackupPro creates tasks in Windows Task Scheduler that run even when the application is closed. Scheduled tasks execute saved profiles automatically.

Creating a Scheduled Task:

  1. Create and save a backup profile first
  2. Go to the Schedule tab
  3. Click ➕ New Schedule
  4. Configure schedule settings:
    • Select profile to run
    • Choose frequency (Daily, Weekly, Monthly)
    • Set time of day
    • Enable/disable task
  5. Click Create Task

Schedule Frequencies:

  • Daily - Runs every day at specified time
  • Weekly - Runs on selected days of week
  • Monthly - Runs on specific day of month

Managing Scheduled Tasks:

The Schedule tab shows all configured tasks with:

  • Task name and associated profile
  • Schedule frequency and time
  • Last run date/time
  • Status (Enabled/Disabled)

For each task, you can:

  • Run Now - Execute immediately
  • Edit - Modify schedule settings
  • Enable/Disable - Turn on/off
  • Delete - Remove completely

Viewing Task History:

  1. Open Windows Task Scheduler (taskschd.msc)
  2. Navigate to Task Scheduler Library
  3. Find BackupPro tasks
  4. View History tab for execution logs
⚠️ Important:
  • Computer must be powered on for tasks to run
  • If using network storage, network must be connected
  • Tasks run with your user account permissions
  • Administrator rights may be needed for some operations

Recommended Schedules:

Backup Type Recommended Frequency Best Time
User Profile Daily 11:00 PM (off-hours)
Documents Sync Daily 6:00 PM (end of workday)
System Image Weekly Sunday 2:00 AM
Project Archives Weekly Friday 5:00 PM
💡 Best Practice:
  • Schedule during off-hours to minimize performance impact
  • Stagger multiple tasks to avoid resource conflicts
  • Test schedules by running manually first
  • Enable email notifications for scheduled tasks
  • Regularly verify backups are completing successfully

    • Default: 465 (SSL)

SMS Text Alerts

Texts your phone via your carrier's free email-to-SMS gateway, using the same Gmail account configured above - no separate SMS service, app, or API key needed.

  • Enable SMS text alerts: master on/off checkbox
  • Phone numbers: click ➕ Add Phone Number and enter a label, the 10-digit number, and the carrier from the dropdown (AT&T, Verizon, T-Mobile, Xfinity/Comcast, Sprint, US Cellular, Boost, Cricket, Metro PCS, Google Fi, Mint Mobile, Visible, Consumer Cellular, or Straight Talk)
⚠️ Carrier Gateway Accuracy: Carriers occasionally change or retire their email-to-SMS gateway addresses. If texts stop arriving, verify your carrier still supports this feature - some (especially prepaid MVNOs) have discontinued it.

ntfy Push Notifications

Free, instant push notifications to your phone or desktop via ntfy.sh - no Gmail account needed for this channel, it's a separate HTTP request.

  • Enable ntfy push notifications: master on/off checkbox
  • Topic: a name you choose (or generate randomly with 🎲 Generate) - install the free ntfy app and subscribe to the same topic name to receive alerts
  • Server: defaults to https://ntfy.sh; change this if you run a self-hosted ntfy server
⚠️ Topic Privacy: Anyone who knows your topic name can read your notifications on the public ntfy.sh server. Keep it random - avoid anything guessable like "backup" or "ronbackups".

Testing Notifications:

Click 📤 Send Test Notification in Settings to immediately test whatever combination of Email/SMS/ntfy is currently filled in and enabled - it reports per-channel success/failure so you know exactly which part of your setup, if any, needs attention.

Setting Up Gmail Notifications:

  1. Go to Google Account settings
  2. Security → 2-Step Verification
  3. App Passwords → Generate new password
  4. Select "Other" and name it "BackupPro"
  5. Copy the 16-character password
  6. Paste into BackupPro Email Password field
  7. Check "Enable Notifications" (and/or "Enable SMS text alerts" if you added phone numbers)
  8. Click "📤 Send Test Notification" to verify

Configuration File:

Settings are stored in backup_config.json in the application directory. Note that the compiled backuppro3.exe in the dist folder keeps its own separate copy there, distinct from the one used when running backuppro3.py directly from the project root.

⚠️ Security:

All credentials (email app password, NAS login, SMS/ntfy settings) are stored in plain text in backup_config.json, matching the rest of the REGTeches tool suite. This is a deliberate, accepted trade-off for a single-user local tool, not an oversight - protect the file accordingly.

  • Never use your regular Gmail password
  • Always use Gmail App Passwords
  • Configuration file contains sensitive data
  • Protect configuration backups appropriately

14. Troubleshooting

Common Issues and Solutions:

Issue: "Administrator Required" Error

Solution:

  1. Right-click backuppro3.exe (or backuppro3.py if running from source)
  2. Select "Run as Administrator"
  3. Or create shortcut with Admin privileges enabled, or accept BackupPro's own elevation prompt on startup

Issue: NAS Shows "Not Configured" or "Offline"

"Not Configured" is expected on a fresh install - BackupPro no longer assumes any particular network or IP address, so this just means no NAS IP has been entered in Settings yet. Enter your own NAS's IP address and click 🔌 Test to confirm it's reachable.

"Offline" Solutions:

  • Verify NAS is powered on and connected to network
  • Check IP address in Settings is correct
  • Ping NAS from Command Prompt, e.g. ping 192.168.1.50 (use your own NAS's IP)
  • Verify firewall isn't blocking connection
  • Try accessing NAS from File Explorer

Issue: WiFi Export Shows "Not Found" for Passwords

Solutions:

  • Run BackupPro as Administrator
  • Some networks use certificate authentication (no password)
  • Enterprise networks may not store passwords locally

Issue: Browser Backup Skips Some Browsers

Explanation:

  • Browser not installed in standard location
  • Portable browser versions not detected
  • Non-standard browser variants

Solution:

  • Manually copy browser profile from:
    C:\Users\Username\AppData\Local\[BrowserName]

Issue: Sync Operation Hangs or Freezes

Solutions:

  • Click ⏹ Cancel to stop operation
  • Check source/destination paths are accessible
  • Verify sufficient disk space at destination
  • Check for locked/in-use files
  • Try running as Administrator

Issue: Email / SMS / ntfy Notifications Not Working

Solutions:

  1. Click 📤 Send Test Notification in Settings - it reports success/failure separately per channel, so you know exactly which one to fix
  2. Verify you're using a Gmail App Password, not your regular password (required for both Email and SMS, since SMS is sent through the same Gmail account)
  3. Check the sender email address is correct and 2-Step Verification is enabled on the Google Account
  4. For SMS: confirm the phone number and carrier are correct - carriers occasionally retire their email-to-SMS gateway
  5. For ntfy: confirm you've subscribed to the exact same topic name in the ntfy app, and that "Enable ntfy push notifications" is checked
  6. Check the spam folder for email notifications
  7. Verify internet connection

Issue: Disk Image Fails with "Cannot backup to same drive"

Solution:

  • Must backup to different physical drive
  • Use external drive or network share
  • Cannot backup C: to C:\Backups

Issue: "Another Backup or Recovery Operation Is In Progress"

Explanation: wbAdmin's internal lock didn't clear cleanly - usually because a prior backup was interrupted (cancelled, app closed, process killed) rather than an actual concurrent backup running.

Solution:

  1. Make sure no backup is genuinely running elsewhere first
  2. On the Disk Image tab, click 🔄 Stuck on "another backup is in progress"? Reset Backup Service
  3. Confirm the dialog - this restarts the wbengine Windows service
  4. Wait for it to fully finish (watch the Activity Monitor) before retrying - starting a new backup while the reset is still running will cause a real collision, not just a stale-lock error
  5. Try CREATE SYSTEM IMAGE again

Issue: Backup to a Mapped Network Drive (e.g. V:\) Fails or Isn't Detected

Explanation: Administrator-elevated processes run in a separate Windows logon session and can't see drives mapped in your normal desktop session.

Solutions:

  • Let BackupPro convert the destination to its real network path when prompted ("Mapped Network Drive Detected") rather than typing the mapped letter manually
  • If prompted for a NAS login, enter your NAS credentials directly (checking "Remember in Settings" saves them for next time) - see 7.2 Backing Up to a NAS / Network Share
  • If it still fails with access denied after providing credentials, double-check the username/password and that the share permits that account

Issue: DISM Capture Fails with "The process cannot access the file"

Explanation: DISM's /Capture-Image isn't VSS-aware like wbAdmin - capturing a live, running C: drive can hit any file a running process has open at that moment (BackupPro pre-excludes common offenders like pagefile.sys, DumpStack.log.tmp, and OneDrive's sync-staging folder, but can't predict every possible one).

Solutions:

  • Click Yes when prompted to open dism.log - it names the exact file that was locked, near the end of the file
  • For a one-off, non-critical file, close whatever app has it open and retry
  • For a fully reliable full-C: capture, use CREATE SYSTEM IMAGE (wbAdmin/VSS) instead, or capture from WinPE Recovery Media where nothing else is running

Issue: Quick Profile Backup Missing Folders

Solutions:

  • Folders may be on OneDrive - BackupPro will still find them
  • Some users don't have all folders (normal)
  • Check Activity Log for details on what was found

Issue: Compression Takes Very Long

Explanation:

  • ZIP compression is CPU intensive
  • Large folders with many files take time

Solutions:

  • Use regular sync mode instead for large backups
  • Exclude unnecessary subfolders before compressing
  • Consider splitting into smaller archives

Log Files:

Check backup_log.txt in the application directory for detailed error messages.

Getting Support:

If issues persist:

  • Check the Activity Log for specific error messages
  • Review backup_log.txt for details
  • Note exact error message or behavior
  • Document steps that led to the issue
  • Contact: the GitHub issue tracker

15. Best Practices

Backup Strategy:

Follow the 3-2-1 Rule:

  • 3 copies of data (original + 2 backups)
  • 2 different media types (internal drive + external/NAS)
  • 1 copy offsite (cloud, different location)

Regular Backup Schedule:

Data Type Frequency Method
Active Work Files Daily Quick Sync to NAS
User Profile Weekly Quick Profile Backup
Full System Monthly Disk Image to External
Archived Projects As Needed Compressed Archive

Storage Best Practices:

Destination Choices:

  • External Hard Drive:
    • Fast, portable, affordable
    • Keep disconnected when not backing up
    • Use for system images and monthly backups
  • Network Attached Storage (NAS):
    • Always available for scheduled backups
    • Accessible from multiple computers
    • Perfect for daily document syncs
  • Cloud Storage:
    • Offsite protection
    • Accessible anywhere
    • Good for important documents

Before Major Changes:

Always create backups before:

  • Windows updates or upgrades
  • Major software installations
  • System modifications or repairs
  • Hardware replacements
  • Registry edits
  • Disk partitioning

Verification:

  • Periodically test restoring from backups
  • Verify backup completed successfully (check log)
  • Browse backup contents occasionally
  • Ensure backups aren't corrupted
  • Check available storage space regularly

Security:

  • Keep external backup drives disconnected when not in use
  • Encrypt sensitive backups
  • Store offsite backups in secure location
  • Use strong passwords for network shares
  • Don't leave backup drives connected during internet usage

Maintenance:

  • Review and clean old backups quarterly
  • Check log file size periodically (max 10MB)
  • Update backup profiles when paths change
  • Test scheduled tasks monthly
  • Document your backup strategy

For IT Professionals:

  • Create standardized profiles for deployment
  • Document backup procedures for clients
  • Set up email notifications for monitoring
  • Keep BackupPro updated to latest version
  • Train end users on basic backup operations
💡 Pro Tip: The best backup is the one that actually gets done! Start simple with Quick Profile Backup, then expand your backup strategy over time.
⚠️ Remember: No backup system is perfect. Multiple backup copies using different methods provide the best protection against data loss.
